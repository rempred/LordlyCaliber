**Lordly Caliber v0.5.61 — Bug Fixes**

- Fixed wrong sprites for named characters, including Tuzt and Giolse. Portraits and combat previews now follow the game’s class and player/enemy lookup rules.
- Fixed inherited attack counts showing 255 and dropdowns assigning the wrong class after deleting a custom class.
- Fixed Testing rejecting new classes against an outdated ROM, and spare inventory blocking required custom equipment.
- Fixed artwork copying and restoration unintentionally affecting other classes’ shared sprites.
- Fixed shorter animation imports breaking loops, and idle animations using frame IDs above 255 freezing the game.
- Fixed misplaced effect previews caused by incorrect character heights or actor selection.
- Fixed repeated retail effects loading invalid resources and softlocking battles.
- Fixed imported effects playing without applying damage/status, and multi-target effects leaving selected units untouched. Results now follow the actual impact timing.
- Fixed New Campaign routing errors and garbled starting-army names.
- Fixed added missions failing during title loading, and briefings crashing when the expected enemy squad was absent.
- Fixed authored victories ending on a black screen instead of returning to the world map.
- Fixed mission/save export compatibility and stale runtime references after removing copied battlefields.
- Added native-code tests using real animation timings for complete battle playback, plus expanded class, artwork, campaign and save regression coverage.
- Verified normal New Game → victory → save/reload → next mission, including added and removed roads. Unedited exports remain byte-identical to the original.
